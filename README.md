# 宜爱家 · 本地 Web 应用

独立运行的家纺商品图设计工作台，支持被子和床上套件、手写首图文案、大模型编写其余图片文案，以及主图和详情页导出。浏览器访问 **http://127.0.0.1:3000**。

工作台界面与交互使用 **Vue 3 + Vite**，采用浅色布局、暖橙色操作按钮和独立的商品编辑流程。Next.js 负责 API、本地存储与可选账户登录，工作台由 Vue 渲染，不依赖 ChatGPT Sites 托管。

## 首次安装

需要 Node.js 24.11+ 和 pnpm。克隆仓库并进入项目目录后执行：

```powershell
pnpm install --frozen-lockfile
pnpm run setup
pnpm build
pnpm start
```

打开 http://127.0.0.1:3000 即可使用。首次安装默认使用本机免登录模式，可直接体验内置样例；使用 AI 时在“自定义 API”中填写自己的接口、模型和密钥。

仓库不包含本机 API Key、用户作品、上传素材、数据库和测试截图。运行数据自动保存在本机 `data/` 中。

## 日常使用

双击 `start-windows.cmd`，服务会在后台启动并打开浏览器。已经启动时直接打开页面，不会重复启动。

关闭浏览器不会停止服务；需要停服时双击 `stop-windows.cmd`。电脑重启后再次双击启动，没有设置开机自启。

默认只监听 127.0.0.1，采用本机单用户模式，无需 ChatGPT 或额外账号登录。同一电脑的用户共用本地作品；此配置不用于公网或局域网部署。

## 操作流程

首页可直接选择“商品主图”“商品详情”或“风格模板”。选择“被子”或“床上套件”类目 → 上传商品图片或 ZIP、标记素材用途并填写已确认卖点 → 逐张安排标题、实拍与顺序 → 实拍或 AI 预览首图 → 确认方向后完成整套 → 编辑、保存、下载。

1 张实拍即可开始，建议准备 5 张整体与细节照片；素材不足时复用已有图片。资料页可直接进入内容计划，也可先选择视觉风格。模板库支持类目、主图/详情筛选，先预览前三张真实排版再使用，不调用图片 API。类目与用途匹配时应用到当前作品，否则使用选定模板新建空白商品。

首页提供当前草稿继续编辑与最近作品；“我的作品”支持按商品名、品牌、图片用途和类目筛选。切换商品前可保存未保存的修改。内容计划中更换原图只重置对应图片，其他已完成图片保留；使用中的素材需先在内容计划中替换再移除。

默认使用“宜爱家店铺”风格，并按类目安排内容：

| 类目 | 5 张主图顺序 | 7 张详情顺序 |
| --- | --- | --- |
| 被子 | 首图、铺床场景、填充与形态、做工细节、颜色对照 | 首屏、卖点总览、面料纹理、填充与形态、做工细节、颜色对照、商品参数与洗护 |
| 床上套件 | 首图、整床搭配、面料纹理、套件组成、颜色对照 | 首屏、花型配色、面料纹理、套件组成、做工细节、颜色对照、商品参数与洗护 |

被子首图优先使用叠放实拍，米白底、黑色短标题与驼橙色卖点突出商品形态；床上套件以整床搭配、上方短标题、奶油色衬底与柔和色块展示花型。素材用途可分别标记叠放、填充、工艺，或被套、床单、枕套。床上套件资料提供“套件组成”字段，按实际填写品项和件数，规格分别填写各部件尺寸；被子资料保留填充物与重量。

内容计划可修改文案、指定原图、调整首屏以外的顺序。首图标题与补充说明由用户手动填写；“AI 生成其他图文案”按商品资料、类目及图片用途，一次生成其余图片的标题与说明，可继续逐张修改或撤销本次生成。调用失败或文案格式不完整时保留原文案；自动文案只改文字，已生成的图片与完成状态保留，核对后点击“保存作品”。生成依据是已填写的资料和图片用途，不会把照片发送给文案模型。

切换类目会保留商品资料、首图文案与原始实拍，清除当前计划中的旧生成结果并重建对应类目的其余标题、选图和顺序，需要重新核对资料与素材用途。修改资料后选择“按最新资料重新规划”会保留首图文案；切换视觉模板保留用途对应模块的文案与原始选图，重新核对新排版后再生成。

店铺风格对首图、整体场景和被子详情卖点形态使用 AI，分别安排陈列、环境与垂感中景；面料、填充、部件、做工、配色与参数保留实拍和真实资料。未填写的材质、功能、规格、套件件数不会自动补造；缺少填充实拍时展示已有商品外观，不合成填充剖面。原始参考图与生成结果分开保存，重做时使用选定实拍，并最多补充两张能识别为同颜色的原图，避免混合色款。建议在素材名称中填写对应颜色，如“米白 · 格纹特写”。颜色未知时只发送选定的一张。

新版按内容变化排版：沉浸首屏、场景低位短信息、面料小图注、工艺近景、花型短叠字、连续配色与克制的参数页。局部编辑可以切换自动分镜、沉浸大图、图文组合和简洁留白，并展开摄影任务及实际参考图。照片可放大到100%–200%，再调整水平与垂直位置；切版和裁切立即预览，不自动发起收费重画。点击重做时才按新构图生成。缺少第二张独立实拍时不重复拼贴。旧作品及三套旧模板仍可打开，未记录类目的旧作品默认按被子处理。

视觉参考采用用户指定的两款商品：[被子参考](https://detail.vip.com/detail-1714230467-6922096046911460931.html)用于叠放大图、面料填充与工艺说明；[床上套件参考](https://detail.vip.com/detail-1714230467-6921823509075762179.html)用于整床花型、柔和色调和部件展示。类目选择与内容计划中可直接打开对应参考。程序使用用户自己的商品图片与品牌文字，不导入参考商品的图片、授权证书或参数。

主图为 5 张 1200×1200 JPEG，详情为 7 张宽 790 的切片，高度随模块内容安排。内置被子样例可以直接体验，无需 API Key；切换为床上套件可试用流程，正式制作时请更换为实际套件的实拍素材。

成图文案默认使用更圆润的“资源圆体”，包含常规、中等和加粗字重。字体随应用保存在本地，主图、详情、模板示例及下载图片统一使用；旧作品打开后自动采用新字体，无需重新生图。字体来源为 [Resource Han Rounded 0.990](https://github.com/CyanoHao/Resource-Han-Rounded/releases/tag/v0.990)，SIL OFL 1.1 许可与来源说明保存在 `public/fonts/`。

AI 生成需要在“自定义 API”填写可用图片接口，调用所配置的服务商并按其规则计费。关闭网页后，剩余 AI 任务不保证继续；已保存的结果保留。

### 自定义 API

应用仅提供自定义 API 配置，新安装不预填服务商或密钥。填写自己的 HTTPS Base URL（也可填写完整的 `images/edits` 地址）、图像模型、文案模型和 API Key。两个模型共用已保存的地址与密钥，文案模型可留空，仅使用实拍排版或图片功能。保存只在本机加密保存配置；连接检测只读取模型列表；文案生成及图片生成会调用各自的模型，费用由所填服务商账户承担。

图片功能需要 OpenAI 兼容的 `multipart/form-data` 图片编辑接口（`POST images/edits`，包含参考图、`model`、`prompt`、`size` 和 `n`），并返回 `data[0].b64_json` 或 `data[0].url`。文案功能需要 `POST chat/completions`，非流式返回 `choices[0].message.content`。两个接口均从同一个 Base URL 派生；聊天模型不会替代图像模型。接口生成的图片由工作台继续排版导出。

设置支持生成质量（自动、高、中、低）和素材尺寸（1K、2K）。旧配置默认自动/1K；自动质量不发送 `quality`，兼容原接口。已验证接入的 B.AI `gpt-image-2` 使用方形主图素材与竖向详情素材；其他自定义服务商保持方形尺寸。高质量与 2K 会增加生成时间和服务商费用，请按其计费规则选择。参考研究和实际验证见 [商拍流程调整](docs/COMMERCIAL-PHOTOGRAPHY.md)。

原有 OpenAI 兼容配置继续显示为自定义 API；原来的供应商专用配置已停用，需要重新填写兼容接口、模型和密钥。修改接口地址时必须重新输入密钥，同一地址保存时可以留空以保留已有密钥。

已验证的 B.AI 配置示例：Base URL 为 `https://api.b.ai/v1`，图像模型为 `gpt-image-2`。开发环境已通过模型列表检测和真实图片编辑，返回 1024×1024 图片。克隆仓库后需填写自己的配置和密钥。

文案模型按用户选择使用 DeepSeek-V4.1-Flash。本机模型列表返回的准确 API ID 为 `deepseek-v4.1-flash`，设置中使用该小写 ID；模型介绍见 [B.AI 模型说明](https://docs.b.ai/llmservice/models/deepseek-v4-1-flash/)，请求格式见 [B.AI API 文档](https://docs.b.ai/llmservice/api/)。本次升级为已有 B.AI 配置补入该文案模型，图像模型与加密密钥保持原值；之后用户可以在设置中修改或清空文案模型。

接口契约依据 [B.AI API Key 页面](https://chat.b.ai/key)的图片编辑调用示例：`POST /v1/images/edits`，单张参考图使用 `image` 文件字段；图片能力见 [GPT-Image-2 说明](https://docs.b.ai/llmservice/image-models/gpt-image-2/)。

## 本地数据

`data/` 保存 SQLite 数据库、上传素材及加密主密钥。备份前先停止服务，再完整复制该目录。不要单独删除 encryption-secret，否则保存的 API Key 将无法解密。

本地数据与旧站点独立；旧站的私有作品及 API Key 不会自动迁入。仓库包含“立体格纹绗缝被”内置样例供体验。

日志：`data/server.log`、`data/server-error.log`。

## 开发与重新构建

需要 Node.js 24.11+ 和 pnpm。源码分工如下：

| 目录 | 用途 |
| --- | --- |
| `frontend/` | Vue 3 工作台、首页、模板、作品、素材、商品编辑与 API 设置 |
| `lib/` | 共用商品模型、文案处理、画布排版及后端数据逻辑 |
| `app/api/` | Next.js API；`app/login/` 提供可选账户登录 |
| `app/route.ts` | 鉴权后返回构建好的 Vue 工作台入口 |

本地开发前先停止生产服务，避免占用 3000 端口：

```powershell
.\scripts\stop-local.ps1
pnpm dev
```

`pnpm dev` 启动两个仅监听本机的服务：Vue / Vite 工作台位于 `http://127.0.0.1:3000`，Next.js API 开发服务位于 `http://127.0.0.1:3002`。浏览器使用 3000 端口，Vite 将 API、登录、样例与字体请求代理到 3002，开发数据仍保存在本机 `data/`。按 `Ctrl+C` 停止开发服务。

构建与检查：

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
pnpm build
```

`pnpm build:ui` 单独检查并构建 Vue 前端，生成到 `public/workbench/`。`pnpm build` 先执行前端构建，再构建 Next.js 生产后端；`pnpm start` 在 3000 端口启动完整应用，无需另外启动 Vite。生产模式中，Next.js 直接返回 Vue 入口 HTML 并提供静态资源与 API。

更新源代码后停止服务、重新构建，再启动。`scripts/verify-http.mjs` 在隔离临时库检查普通账号模式，包含 Vue 入口与脚本/CSS、上传、保存、权限、自定义 API 配置、旧配置兼容与停用、重启持久化；验证服务拦截外部 API 请求，不调用真实模型。

本次验证见 docs/VERIFICATION.md。
